Guia da estrutura do projeto

O que é cada pasta, o que cada arquivo faz e os conceitos essenciais para começar a mexer no código.

Base: 1ª entrega (aula 28/08) — solução criada, banco modelado, primeira migration aplicada.

1. O que é o sistema

PokéDraft é um simulador de batalha Pokémon entre dois jogadores. O jogo tem três fases:

  • Draft de Pokémon — o sistema sorteia vários samples (pacotes) de Pokémon, iguais para os dois jogadores. Cada jogador tem um orçamento em pontos; cada Pokémon tem um custo. Dá para banir e comprar Pokémon. Se os pontos acabam, o jogador pode vender um Pokémon do time (recebe menos do que pagou) para liberar pontos.
  • Draft de itens — um único pacote com todos os itens de batalha, compartilhado. Cada item pode ser equipado em um Pokémon, somando ao overall dele.
  • Simulação da batalha — cada jogador escolhe a ordem do time. Os times se enfrentam 1×1 (1º contra 1º, etc.). Cada duelo vencido vale 1 ponto; quem fizer mais pontos vence. Empate 3–3 → decide a média do overall.

Overall = status base do Pokémon + item equipado + natureza + IV. Na batalha entram bônus por vantagem de tipagem, velocidade e tipo de ataque.

Fora do escopo: várias gerações, draft de golpes (moveset), escolher IV/natureza manualmente.

3. Como rodar (primeira vez)

Pré-requisitos por máquina: .NET SDK 8, Git, VS Code (extensões C# e C# Dev Kit) e a ferramenta do EF Core:

dotnet tool install --global dotnet-ef --version 8.*

Depois:

git clone https://github.com/eduardowoz/PokeDraft-DesenvolvimentoSoftwereVIsual.git
cd PokeDraft-DesenvolvimentoSoftwereVIsual
dotnet restore
dotnet ef database update --project PokeDraft.Web   # cria o pokedraft.db
dotnet run --project PokeDraft.Web

O terminal mostra um endereço (http://localhost:5xxx) — abra no navegador.

Backend — Data e Migrations

ArquivoO que faz
Data/PokeDraftDbContext.csA ponte entre as classes e o banco. Tem um DbSet<T> por entidade (= uma tabela), configura os relacionamentos (quem aponta para quem, o que acontece ao apagar), os índices e um dado inicial (uma Configuracao “Padrão”).
Migrations/…_InicialCreate.csA primeira migration. Método Up() = comandos que criam todas as tabelas; Down() = como desfazer. Gerado automaticamente pelo comando dotnet ef migrations add.
Migrations/…_InicialCreate.Designer.csMetadados dessa migration (usado pelo EF Core internamente). Não se edita à mão.
Migrations/PokeDraftDbContextModelSnapshot.cs“Foto” do estado atual do modelo. O EF compara com as suas classes para descobrir o que mudou quando você cria a próxima migration.

7. Conceitos rápidos

MVC (Model — View — Controller)

Jeito de separar responsabilidades: Model = os dados e as regras · Controller = recebe o pedido e coordena · View = o HTML que o usuário vê. Analogia do restaurante: cozinha (Model), garçom (Controller), mesa servida (View).

Entity Framework Core

É o ORM: em vez de escrever SQL na mão, você mexe em objetos C# e o EF traduz para o banco. _context.Pokemons.Add(p) + SaveChanges() vira um INSERT.

Migration

Um “commit” do formato do banco. Fluxo: você muda/cria classes em Models/Entities/ → roda os comandos abaixo → o EF gera o código e aplica no seu pokedraft.db.

dotnet ef migrations add NomeDaMudanca --project PokeDraft.Web
dotnet ef database update --project PokeDraft.Web
A pasta Migrations/ vai para o Git junto com a mudança nas classes. O arquivo pokedraft.db não vai. Quem dá git pull e recebe migrations novas roda só dotnet ef database update.

API + fetch

O Controller devolve JSON; o JavaScript no navegador chama com fetch() e monta a tela. Verbos: GET busca · POST cria · PUT atualiza · DELETE remove. A rota no JS tem que ser idêntica à rota do Controller.

const resp = await fetch("/api/pokemons");
const lista = await resp.json();

8. Fluxo de trabalho da equipe

  • A branch main tem que sempre compilar e rodar. Ninguém commita direto nela — cada tarefa em um branch + Pull Request.
  • Antes de commitar: dotnet build sem erros.
  • Deu git pull e veio migration nova? Rode dotnet ef database update.
  • Cada card do Trello = uma tarefa de uma aula. Mova o card para "Em desenvolvimento" quando começar e para "Concluído" quando o PR entrar.
